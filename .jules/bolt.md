## 2024-05-14 - Zero-Allocation Version String Parsing
**Learning:** String concatenation and array allocation in tight loops (like `versionItems[dotCount] += c;`) followed by `int.TryParse` cause significant allocation and performance overhead when called frequently (e.g., during bulk package version comparisons). In C#, using integer multiplication (`buffer * 10 + (c - '0')`) while directly traversing string characters entirely eliminates these intermediate allocations.
**Action:** When optimizing tight loops that process string characters into numeric representations, avoid string concatenation and intermediate string arrays. Instead, traverse the string character by character and construct the numeric value mathematically inline. Utilize `long` buffers to explicitly replicate the overflow-ignoring semantics of `int.TryParse` (which returns 0 if overflow limits are exceeded) before casting back to `int`.
